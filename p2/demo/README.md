# `p2/demo/` — 演示视频的选片与合成

PDF §6.2 要求提交处理后的视频。这里说明演示片是怎么挑 clip、怎么合成的；
**视频本体不入库**（6 个 clip × 普通版/带 loupe 版共 11 个 1080p mp4，约 140 MB），
需要时按下面的命令在服务器上重新生成。

## 1. 为什么不能随便挑一个 clip

指标上 EDVR 在 30 个 clip 上全胜，但"投影仪上看得出差别"是另一回事：需要**GT 本身细节多**、
**bicubic 破坏得狠**、且**方法确实把纹理补回来了**。所以先排序再选片。

`scripts/mk_vis_rank.py` 在 GT 的第 10/30/50/70/90 帧上算三个量：

| 量 | 定义 |
|---|---|
| `detail` | GT 的 mean \|Laplacian\| —— 画面里到底有多少细节 |
| `loss_bic` | `1 − grad(bicubic)/grad(GT)` —— bicubic 把这些细节破坏了多少 |
| `rec_edvr` / `rec_teco` | `grad(方法输出)/grad(GT)` —— 方法把纹理补回了多少 |

排序键是 `sqrt(detail) × loss_bic`（先保"有细节可看"，再看"破坏程度"）。
结果落在 `metrics/visibility_rank.json`，30 个 clip 全在里面。

> 这是个粗排索引，不是指标：`grad` 用的是 Sobel 幅值均值，`rec > 1` 只说明锐度超过 GT，
> 不等于更接近 GT（TecoGAN 的 GAN 纹理就容易把 `rec` 顶上去）。只用来挑演示片。

## 2. 入选的 6 个 clip

`002 / 011 / 013 / 015 / 016 / 018` —— 兼顾"纹理型"（011 是砖墙/屋檐类强细节）与
"文字细线型"（015/018 有招牌、路面标线）。

静态预览：本目录的 `picks_sheet.png`（2880×1080，6 个 clip × 2×2 面板，取自第 45 帧），
不含 loupe，只用来一眼看差别；判断纹理与闪烁仍要看视频。

> 选片逻辑是"看得出差别"，不是"选个体面的例子"：这 6 个 clip 的 EDVR 相对 bicubic 增益
> 都不是最极端的，选的是细节密度高、缩放后差异可见的那几个。

## 3. 合成脚本

`scripts/p2_demo_2x2.py`，输出 1920×1080 / **24 fps**（REDS 源帧率）/ H.264：

```
+---------------------+---------------------+
|        GT           |      Bicubic        |
+---------------------+---------------------+
|       EDVR          |      TecoGAN        |
+---------------------+---------------------+
```

```bash
python p2/scripts/p2_demo_2x2.py 002 011 013 015 016 018          # 普通版
python p2/scripts/p2_demo_2x2.py --inset 002 011 013 015 016 018  # 右上角 2× 放大 loupe
```

前置条件：GT（`val_sharp/`）、bicubic（`val_sharp_bicubic/`，脚本内重采样）、
EDVR 帧、TecoGAN 帧都已落盘。缺任一方法的帧时会渲染成带标签的占位块并继续，
不会中断整条视频，也不会静默错位。

## 4. 这一版修掉的四个问题

| 问题 | 旧行为 | 现在 |
|---|---|---|
| 裁剪窗口越界 | clip 013 上 `cv2.resize` 收到空 slice 直接崩（`!ssize.empty()`） | `loupe` 按真实图像尺寸裁剪，装不下时退回中心裁剪 |
| 帧配对方式 | 按排序后的位置配对，某方法缺一帧就整段错位 | 按**解析出的 frame id** 配对，缺帧即缺帧 |
| 缺帧处理 | 抛异常 | 渲染带标签的占位块，日志里报告缺了哪些 id |
| ffmpeg 失败 | 只留半截文件 | 收 stderr 报错、删除半截文件、退出码非 0 |
