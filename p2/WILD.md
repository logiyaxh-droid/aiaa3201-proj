## 4. 结果

### 4.1 汇总（20 片段 × 100 帧）

| 方法 | PSNR↑ | SSIM↑ | LPIPS↓ | tLPIPS↓ |
|---|---|---|---|---|
| Bicubic | 27.017 | 0.7953 | 0.3337 | 0.0280 |
| Lanczos | 27.139 | 0.7992 | 0.3325 | 0.0279 |
| Bicubic+USM | 27.439 | 0.8115 | 0.2842 | 0.0379 |
| EDSR ×4 | 29.100 | 0.8572 | 0.1822 | 0.0546 |
| 3 帧平均 | 25.173 | 0.7313 | 0.3925 | 0.0245 |
| 5 帧平均 | 24.233 | 0.6990 | 0.4329 | 0.0200 |
| 5 帧平均+USM | 24.440 | 0.7104 | 0.3854 | 0.0267 |
| 光流对齐 3 帧 | 26.997 | 0.7934 | 0.3484 | 0.0098 |
| **光流对齐 5 帧** | 26.929 | 0.7909 | 0.3559 | **0.0060** |
| 光流对齐 5 帧+USM | 27.459 | 0.8104 | 0.3104 | 0.0084 |

| **TecoGAN** | 26.123 | 0.7662 | 0.2014 | 0.0406 |

### 4.2 三条结论

**① 多帧对齐的收益是倒 U 形，不是"越难越大"。**

| 源 | bicubic PSNR | EDVR − EDSR | 片段胜率 |
|---|---|---|---|
| A | 22.36 dB | +1.07 dB | 4/4 |
| **D** | 23.20 dB | **+2.67 dB** | 4/4 |
| E | 28.85 dB | +1.44 dB | 4/4 |
| C | 29.66 dB | +1.53 dB | 4/4 |
| B | 31.01 dB | +0.25 dB | 2/4 |

峰值在 **D**：手持运动 + 高频纹理 + 低光噪声三个条件齐备。
两端衰减原因不同 —— A 的主体物理尺寸太小（行人仅 30–45 像素，4 倍下采样后剩 8–11 像素），
B 是手机预处理把细节和噪声一起抹掉了，多帧无可对齐。
**C 是规律的反例**：bicubic 已有 29.66 dB 看似不难，但走廊的强透视运动让 EDVR 仍拿到 +1.53 dB。

**② tLPIPS 轴上，最简单的光流对齐最强（20 个片段全部一致）。**

光流对齐 5 帧 `0.0060` vs EDVR `0.0399`，前者只有后者的 **1/6.7**。这不是缺陷：
全分辨率光流 warp + 加权平均本身就是极强的时域低通，代价是空间细节（PSNR 26.9 vs 30.5）。
三个方法各占权衡图的一个角。

**③ TecoGAN 在 20/20 个片段上 LPIPS 全部输给 EDVR。**

| 源 | TecoGAN LPIPS | EDVR LPIPS |
|---|---|---|
| A | 0.2503 | **0.1553** |
| B | 0.1636 | **0.1119** |
| C | 0.1590 | **0.1332** |
| D | 0.2453 | **0.1699** |
| E | 0.1886 | **0.1395** |

原先的假设是"GAN 在真实退化上可能反超 EDVR"，**实测未观察到**。
说明瓶颈在 ×4 大倍率下的重建能力，与退化域是否为合成关系不大。

## 5. 口径说明（引用本目录数字时必须一并说明）

1. **没有真 GT。** 把手机原片当 GT，用 σ=1.5 高斯 + 双三次 4 倍下采样生成 LR。
   该核是拿课程官方 REDS LR 标定出来的（吻合度 **42.38 dB**，纯双三次仅 27.17 dB）。
   因此这是 **真实内容 + 合成退化**，只有内容是真实的，退化不是。

2. **A 的 GT 是 1072×720（LR 268×180），其余四源为 1280×720（LR 320×180）。**
   A 是竖屏源，为保持 3:2 构图如此裁切。跨源比较时应以每源内部的相对排序为主。

3. **裁切窗口按运动自动选择，但只有 A 真正选准。**
   判据是"光流减中位流场后的残差峰值"（纹理判据会选到无运动的建筑立面，帧差判据被
   相机整体漂移淹没，两者都已废弃）。C/D/E 为手持前进拍摄，画面径向膨胀导致残差全图
   偏大，选窗退化并自动回退到居中，日志标记 `[FLAT]`。

4. **EDVR 每次前向只处理 5 帧**（`num_frame=5, center_frame_idx=2` 的滑窗），
   不是 100 帧。100 帧 = 100 次前向，显存占用与视频长度无关。

## 6. 复现

```bash
# 1) 建 GT/LR（自动选窗，固定 1280x720 窗口 -> LR 320x180）
python prep_auto.py /tmp/VID_xxx.mp4 <源字母> 4

# 2) 指标
python p1_wild.py  gt lr part1          # Part 1 的 10 个方法
python p2_edvr_wild.py gt lr part2      # EDVR
bash   p2_teco_wild.sh gt lr part2      # TecoGAN（CPU，含 0.375px 对齐修正）
python p2_teco_metrics_wild.py gt part2

# 3) 汇总与图
python table_all.py
python figs_all.py && python figs_ladder.py

# 4) 2×2 演示视频（边算 EDVR 边编码，不落盘中间帧）
python demo_2x2.py A00 B00 C00 D00 E00
```

`demo_2x2.py` 与 `p2_demo_2x2.py` 的区别：后者读四路 PNG 序列，前者因为磁盘放不下
20 片段 × 100 帧的 EDVR 输出，改为**边推理边送入 ffmpeg 管道**，中间帧不落盘。
输出格式（分辨率/帧率/编码/CRF/布局/标注）与 `p2_demo_2x2.py` 完全一致。
