# 后续探索路径：补齐感知指标，定位现有 VSR 方法的质量局限

版本：2026-11-19（计划文档，尚未开始安装或正式跑分）

## 0. 目标与边界

本轮只回答一个问题：**在保持现有 PSNR / SSIM 结果不变的前提下，现有方法在结构、纹理、自然观感和视频技术质量上分别差在哪里？**

先做测量，不先选改进算法。DISTS、MUSIQ、DOVER 是诊断工具，不是“分数越高，画面越接近真实视频”的通用证明。指标补齐以后，用区域、运动强度和时序片段解释分数差异，再针对一个已证实的缺陷做最小干预。

本轮暂不包含：训练新模型、加入 Flow Matching 或 STAR、扩展真实退化数据集、用多个指标合成一个总分。新数据集留到“泛用性”阶段；不把两类问题混在一次实验里。

## 1. 已知起点

### 1.1 已有资产

- 共享评测代码位于 `p0/evalkit/`；`full_eval.py` 已经统一 PSNR、SSIM、LPIPS(Alex)、tLP、Flow-warp LPIPS 和 FID 的口径。
- 当前汇总覆盖 REDS 验证集 30 clip × 100 帧 × 12 方法，共 3000 帧。现成结果见 `p0/out/full/summary/table.md`。
- P3 已有少量诊断输出：TTA、不确定性、路由、软融合和注意力实验。TTA 在 `000/002/009` 上的 PSNR 分别增加 `0.115/0.135/0.074 dB`，但三个片段的 LPIPS 都略微变差；这不能直接解释成“感知质量下降”，要用新增指标复核。
- 当前路由实验的对象是 EDVR 与 BasicVSR++；Real-ESRGAN 路由是另一条更早的负结果。报告时必须区分实验对象。

### 1.2 本轮不能直接沿用的东西

`full_eval.py` 是“生成一帧、评分、随后丢弃”的流式脚本。除 TecoGAN 等已有缓存外，其他方法的新增逐帧指标需要重新生成预测帧。因此不能假装新增指标只需读取旧 JSON。

应优先复用已有的合法预测缓存；缓存不完整时，沿用原模型、权重、输入和 uint8 量化方式重新生成。不要从展示视频中解码帧代替原始输出，视频压缩会同时改变纹理和时序指标。

### 1.3 环境和资源的前置约束

2026-11-19 的只读检查显示：`/tmp/srenv` 已有 PyTorch 2.6.0、torchvision 0.21.0、LPIPS 和 OpenCV，但没有 `pyiqa`、`decord` 或 `av`。当时根分区与数据分区都接近满，GPU 是共享的 RTX A6000。执行前必须重新检查：

```bash

```

新环境优先放在用户目录的独立 venv，或者确认有空间后放在 `/tmp`。不要在共享 Conda 环境上原地升级 PyTorch、torchvision、timm 或 NumPy；DOVER 的依赖可能和 BasicSR 环境冲突。安装前记录 `pip freeze`，安装后复跑一个已有 LPIPS 数字，确认旧指标没有漂移。

## 2. 三个指标各自回答什么

| 指标 | 是否需要 GT | 本轮用途 | 不能说明什么 |
|---|---|---|---|
| **DISTS** | 需要，逐帧配对 | 衡量结构与纹理相似性；定位“纹理自然但内容错了”与“内容对但纹理过软” | 不能单独证明画面真实；它仍受训练分布和特征模型影响 |
| **MUSIQ** | 不需要 | 用多尺度图像质量模型检查单帧自然观感，观察方法是否只是让画面更锐或更“像照片” | 不使用 GT，不能证明纹理来自 GT，也不能判断时序一致性 |
| **DOVER** | 不需要 | 分别检查视频技术质量和美学质量，观察整段视频，而非只看平均单帧 | 主要面向用户生成视频；不能代替逐像素误差、tLP 或真实性判断 |

固定主版本：**DISTS 用官方作者权重；MUSIQ 主版本用 `koniq10k`；DOVER 用原版，而不是为省时间换成 DOVER-Mobile。** 如果实现库默认值不同，以显式配置为准，并把模型名、权重名、权重哈希、代码版本和输入预处理写进结果 JSON。

MUSIQ 的 `paq2piq` 或 `spaq` 只作为敏感性检查，不在第一轮同时跑所有版本。DOVER 的技术分、美学分和融合分分别保存，不拿融合分替代两个分支。第一轮统一用完整原始分支配置；任何降采样、缩短片段或 Mobile 版本都标为快速调试，不进入正式表。

## 3. 统一评测协议

### 3.1 数据集和方法范围

**主实验：** REDS `val_sharp` 的 30 个 clip，每段 100 帧，×4 bicubic LR；预测输出为 1280×720 RGB PNG。保留当前 12 个方法，保证新旧表能直接连接：

`bicubic / lanczos / bicubic_unsharp / edsr / tavg3 / tavg5 / tavg5_unsharp / flowtavg3 / flowtavg5 / flowtavg5_unsharp / edvr / tecogan`

**小规模复核：** P3 的 `000 / 002 / 009` 三个片段，以及现成可复算的 BasicVSR++、Real-ESRGAN、软融合、TTA 输出。这里用于检查已有 P3 结论，不纳入 12 方法主排名。

**隔离原则：** Vimeo 只有中心帧 GT，不能沿用 REDS 的视频协议计算完整 DOVER 或 tLP；自拍视频没有 GT，不能计算 DISTS。三者分表保存，禁止把缺值写成 0。

### 3.2 输入与聚合

- DISTS：预测帧和 GT 都按 RGB、uint8 读入，再转 `[0,1]` float tensor；禁止一个按 RGB、另一个按 BGR。先做全帧，不裁边。每帧一个值。
- MUSIQ：只输入预测帧，使用实现库标准多尺度预处理和所选权重。每个 GT 帧也计算一次，作为数据域参照，不作为“理论满分”。
- DOVER：以完整 100 帧 clip 为输入，使用固定采样种子和官方 `dover.yml` 的片段长度、间隔、空间采样。REDS 每段同样长度，分数才有直接可比性。对 GT 视频也计算一次。
- 聚合：DISTS / MUSIQ 同时保存逐帧值、每 clip 均值和中位数；主表用“30 个 clip 的均值”，附 clip 间标准差。DOVER 每 clip 一个值。主表不能只报 3000 帧混合均值。
- 分数方向：DISTS 越低越好，MUSIQ / DOVER 通常越高越好；结果读取时用实现接口再次确认，不靠记忆。
- 所有运行保存精确帧 ID 列表、输出分辨率、颜色通道、量化方式、预处理、采样种子、耗时、GPU 型号和软件版本。

### 3.3 指标自检

必须先做，再做全量：

1. **恒等检查**：预测 = GT 时，DISTS 应接近 0；记录实际浮点误差。
2. **退化单调性抽查**：在固定 10 帧上构造模糊、噪声、压缩、局部错位和人工锐化。DISTS 对严重失真应总体增大；MUSIQ / DOVER 不要求对所有失真单调，但必须记录响应方向。
3. **参考实现复核**：至少 10 对图上比较 DISTS 接入实现与官方 `DISTS_pytorch`，约定绝对误差阈值 `< 1e-5`。若使用 pyiqa 的 DISTS，需要同时固定 VGG 与 DISTS 权重。
4. **重复性**：同一 clip 连跑两次；逐帧指标应一致到浮点误差，DOVER 的采样结果必须可复现。
5. **旧指标回归**：任选 `000` 的一个方法，新环境计算的 PSNR / LPIPS 与旧结果一致；PSNR 容差沿用现有验证逻辑，LPIPS 建议 `< 1e-6`。
6. **合理性抽查**：Bicubic、EDVR、TecoGAN 各看一组逐帧分数和对应图像。如果某指标给出与明显视觉错误相反的异常高分，先停止汇总，检查预处理和实现。

## 4. 分阶段执行

### 阶段 A：安装、冻结实现、跑通一个片段

**目标：** 证明三个指标在同一输入上的实现可信，不是先追求跑完。

1. 建立独立环境并安装：DISTS 官方实现或经验证的 pyiqa 实现；MUSIQ 可用 pyiqa；DOVER 用官方仓库与其兼容依赖。
2. 固定权重与代码版本，保存 SHA256 和环境清单。
3. 只跑 clip `000` 的 `bicubic / edsr / edvr / tecogan`，加 GT 的 MUSIQ 和 DOVER。
4. 完成第 3.3 节自检，记录每帧 / 每段耗时和峰值显存。
5. 根据实测决定批量大小。不要用中位数估计共享 GPU 的稳定速度；基准报告取几次干净运行的最小值，同时保留离散程度。

**产出：** `metric_selfcheck.json`、`environment.json`、clip `000` 的结果和速度记录。

**通过条件：** 恒等、参考实现复核、重复性和旧指标回归全部通过。任何一项失败，只修该问题，不扩到全量。

### 阶段 B：小规模回答“新增指标是否带来新信息”

**样本：** 固定 `000 / 002 / 009`；方法先用 `bicubic / bicubic_unsharp / edsr / edvr / tecogan`。选取这三段是因为已有 P3 输出可复核，不代表它们足以支撑最终结论。

**比较：** 为每一对方法记录 `ΔDISTS / ΔMUSIQ / ΔDOVER技术 / ΔDOVER美学`，并和现有 `ΔPSNR / ΔLPIPS / ΔtLP / ΔFID` 放在一起。

**要回答的三个问题：**

1. DISTS 是否与 LPIPS 给出不同排序？若不同，定位到具体帧和区域。
2. MUSIQ 或 DOVER 是否偏爱某种锐化或生成纹理，而 DISTS / PSNR 同时变差？若是，这就是“观感提升但内容失真”的候选证据。
3. DOVER 技术分与 tLP 是否发现相同的时序问题？若不同，不直接宣布谁错，要检查 DOVER 的采样覆盖和 tLP 的定义。

**产出：** 5 方法 × 3 clip 的新旧指标表、指标差值表、10 组配对局部图。

**停止条件：** 若三段的指标排序完全相同，也不提前宣布“新指标无用”；只能说明这三个片段没有显示增量，仍需阶段 C 的全量统计。

### 阶段 C：REDS 全量测量

**范围：** 12 方法 × 30 clip。按 clip 断点续跑，每个方法完成后原子写入 JSON；DISTS / MUSIQ 的逐帧数组可保存为压缩 NPZ，但只保留数值，不额外长期保存 12 套预测 PNG。

**顺序：** 先 DISTS，再 MUSIQ，最后 DOVER。每完成一个指标先汇总检查，避免一个预处理错误扩散到全部任务。

**主表：**

- 方法级均值与 clip 间标准差；
- 每方法的逐 clip 最好 / 最差片段；
- 相对 Bicubic 与 EDVR 的配对差值；
- 新指标与现有指标的排序对照；
- 运行耗时与覆盖率，缺帧必须显式标出。

**产出：** `reds30_metrics.csv`、逐 clip JSON、汇总表和排序变化图。

### 阶段 D：把“分数差”定位成可观察的局限

这一阶段不新增模型，只解释阶段 C 的差异。

#### D1. 区域归因

使用相同的 16×16 或 32×32 网格；块大小先固定，不做多尺度扫荡。每个块保存：

- 均方误差或绝对误差；
- 高频能量（拉普拉斯响应）；
- 局部梯度差；
- 光流幅度和前后向一致性；
- 两方法 DISTS 的差值。

先为 PSNR 高但 DISTS 差、PSNR 低但 MUSIQ 好的帧建立候选池，再抽块。不要把 DISTS 当作天然可分解的逐像素指标；当前标准实现给整帧分数。若需要块级 DISTS，必须标为“局部裁切诊断”，不能与整帧主分数混称。

按区域输出四类典型例子：

1. **结构错位**：边缘位置错误，PSNR 与 DISTS 同时差；
2. **纹理缺失**：结构大致正确，但高频不足，DISTS / MUSIQ 给出额外信号；
3. **虚假纹理**：MUSIQ 可能变好，但 DISTS / PSNR 变差；
4. **锐化副作用**：锐化分数改善，却伴随光晕或噪声放大。

#### D2. 运动分组

沿用已有运动强度三分位划分，分别统计各组新指标和方法胜负。重点验证：

- EDVR 相对 EDSR 的收益是否随运动变化；
- 光流平均在低运动和高运动组的失败模式是否不同；
- TecoGAN 的感知表现是否只在特定运动组改善。

报告每组的 clip 数和离散程度。三个片段不能支撑组间结论。

#### D3. 时序异常定位

DOVER 是整段分数，不能指出哪一帧闪烁。对 DOVER 技术分最差的片段，联合查看：

- 正式 tLP 的逐相邻帧值；
- Flow-warp LPIPS；
- 相邻帧差分与局部静态区变化；
- 最差相邻帧的三联图：GT、方法 A、方法 B。

用“片段 → 相邻帧 → 局部区域”缩小问题。DOVER 技术分与 tLP 不一致时，分别报告，不强行统一。

#### D4. 指标敏感性

只对阶段 D 找出的代表片段做：

- MUSIQ 第二权重版本；
- DOVER 采样种子重复；
- 图像编码 PNG 与展示视频 H.264 的对照（只用于说明压缩影响，不进入主表）。

若结论随权重或采样完全反转，最终结论只能写成“该指标在此设置下不稳定”。

**产出：** 按缺陷类型组织的案例表、运动分组表、时序异常表，以及每条结论对应的帧 ID 和图。

### 阶段 E：最小干预实验

只有阶段 D 给出明确靶子后才做，且一次只改一个因素。

| 已观察到的现象 | 最小干预 | 主要判据 | 不作什么推断 |
|---|---|---|---|
| EDVR 结构对但纹理偏软，DISTS 明显差 | 在 3 个诊断 clip 上扫描一个轻量锐化或残差高频幅度 | DISTS、PSNR、MUSIQ 与局部光晕共同检查 | 不宣称恢复了真实纹理 |
| 锐化让 MUSIQ 变好但 DISTS / PSNR 变差 | 把锐化幅度作为单变量扫描 | 画出保真—观感权衡，而非选最高 MUSIQ | 不把 MUSIQ 增益当质量提升 |
| TTA 的 PSNR 增益稳定但 DISTS / MUSIQ 无改善 | 保留现有 TTA，不再扩大集成 | 确认收益仅限像素精度，成本是否值得 | 不继续增加翻转或模型 |
| 静态区域闪烁，DOVER 技术分与 tLP 同时支持 | 只对一个静态区时序平滑规则做原型 | 静态区 tLP / 差分、运动区清晰度、DOVER | 不把平滑运动区当时序改进 |
| 各指标排序基本一致，未暴露新缺陷 | 停止干预，完成指标局限说明 | 用覆盖率与逐 clip 结果支持结论 | 不为制造创新点而加模型 |

**干预顺序：** 诊断 clip 3 个 → 若有效，扩展到 10 个固定 clip → 最后才跑 30 个。若第一轮没有收益，记录负结果，不连续尝试多个无关修复。

## 5. 统计与判读规则

1. **配对优先。** 同一 clip、同一帧、同一输入下比较方法；不只比较全体均值。
2. **方向分开。** 保真指标（PSNR / SSIM / DISTS）与自然观感指标（MUSIQ / DOVER）不合成总分。反向变化时，结论就是权衡，而不是“全面更好”。
3. **GT 分数是参照，不是上限。** MUSIQ / DOVER 中某个输出超过 GT，不表示它比 GT 更真实。
4. **相关不代表可靠定位。** 可计算逐 clip 的 Spearman 相关及 bootstrap 置信区间，但不能仅凭相关高就声称某指标可以解释另一种误差。
5. **小规模结果不升格。** `000/002/009` 用于定位；最终方法排名必须回到固定 30 clip。
6. **不隐去反例。** 指标与视觉判断冲突的案例应单独列出，这可能正是指标本身的适用边界。
7. **失败也有结论。** 若新指标没有改变任何方法排序，应写清“在当前 REDS bicubic 设置下未提供额外排序信息”，不能推广到真实退化或其他生成模型。

## 6. 最终需要回答的问题与交付物

### 6.1 结论文档必须回答

- 哪个方法在像素保真之外仍有明显结构或纹理缺陷？出现在哪些片段、运动和区域？
- 哪个方法提升的是自然观感，哪个方法提升的是对 GT 的忠实度？二者在哪里冲突？
- DOVER 的技术分补充了什么视频级现象？它是否和现有 tLP 一致？
- TTA、软融合或路由的已有结论是否被新指标改变？
- 哪个缺陷值得进入下一轮改进？为什么不是其他缺陷？

### 6.2 文件结构建议

```text
p3/quality_metrics/
  README.md
  configs/                 # 冻结的指标、数据与采样配置
  selfcheck/               # 参考实现、恒等、重复性和旧指标回归
  results/reds30/          # 每 clip JSON / NPZ，支持断点续跑
  results/p3_subset/       # P3 分支的独立复核，不混入主排名
  summary/                 # 主表、配对差值、排序变化、运动分组
  cases/                   # 代表帧、局部图、时序异常，不长期保存全量预测
  logs/
```

结果 JSON 至少含：`clip`、`method`、`frame_ids`、`metric`、`score`、`model_version`、`weights_sha256`、`preprocessing`、`runtime`、`coverage`。所有汇总脚本从原始结果生成，不手工改表。

## 8. 实现依据

- DISTS 论文与官方实现：[Ding et al., *Image Quality Assessment: Unifying Structure and Texture Similarity*](https://github.com/dingkeyan93/DISTS)。官方说明其目标是结构与纹理相似性，输入 RGB `[0,1]`。
- MUSIQ 论文：Ke et al., *Multi-Scale Image Quality Transformer*, ICCV 2021；实现参考 [IQA-PyTorch](https://github.com/chaofengc/IQA-PyTorch)。
- DOVER 论文与官方实现：[Wu et al., *Exploring Video Quality Assessment on User Generated Contents from Aesthetic and Technical Perspectives*](https://github.com/VQAssessment/DOVER)。官方推理脚本分别产生技术、美学分支，并提供融合分。
- 本文档只确定实现与实验设计；安装、参考实现一致性和实际排名均尚未验证，正式数字以自检和全量结果为准。
