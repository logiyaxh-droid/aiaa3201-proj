# M2-B 结果：UA-RealBasicVSR（像素空间多帧不确定性加权微调）

日期：2026-11-25 / 26
范围：Part 3 · M2-B，绕开 SD 2.1 的 8× VAE 瓶颈，改在像素空间做端到端多帧微调
判定口径：REDS-Real c9 开发集 `000 / 002 / 009`，27 帧，与 M1 同一套
`score_reds_real.py`

## 结论先说

**方向对了，但三项门槛没有任何一臂能同时跨过。** LPIPS 从 0.4358 降到
**0.40118（改善 7.94%）**实现了真正的感知提升，`DISTS` 降 24.5%，
但代价是 PSNR 掉 0.503 dB、`E_warp` 恶化 19.3%。三个臂各自只差一项，
构成一条清晰的单调权衡。

与 Stage A 对比：**LPIPS 的方向被彻底翻转**（Stage A 五臂最好也只是 +4.9% 变差，
现在 −7.9% 变好）。这说明"放弃 8× VAE、回到像素空间"的判断是正确的。

仍未达标的性质变了：不再是"路线不成立"，而是"**感知—保真—时序三角已画满**，
要同时达标必须换手段而不是调权重"。

## 三、核心发现：三者是硬权衡，不是调参不到位

把感知权重从 `0.15→0.25`、像素从 `0.50→0.35`，三个指标**全部**朝预期方向移动，
但幅度不对等：

| 变化 | LPIPS | PSNR | E_warp |
|---|---|---|---|
| B1 → B2b | 0.40622 → 0.40118（**好 1.2%**） | −0.159 → **−0.503 dB**（差 0.34） | 5.046 → **6.150**（差 21.9%） |

**感知提升 1.2% 的代价是保真掉 0.34 dB、时序掉 21.9%。** 这条斜率已经由两臂实测钉住，
继续沿同方向调参只会更偏离 PSNR/E_warp 门槛。

另一个可分离的发现：**`λ_t` 从 0.30 降到 0.20 是错的方向。** B2b 同时改了三个权重，
其中 `E_warp` 从 5.132 恶化到 6.150（+19.3%），而 B1/B2 在 `λ_t=0.30` 下
E_warp 都还能守住。降低时序权重与感知权重提高两个因素叠加，无法在本次数据里分离，
但方向上 `λ_t` 应当提高而不是降低。

**`tLP` 与 `E_warp` 给出相反结论**：B2b 的 tLP 最好（0.05189，+6.9%）却
E_warp 最差（6.150，+19.3%）。这再次印证 M1 的结论——判断时序稳定性要看
`E_warp`，`tLP` 会被 d_SR 的整体压低带偏。

## 四、B2（不确定性加权）没有赢过 B1（均匀）

这是必须如实记录的负面结果。两臂**均值严格对齐**（自检第 5 项：均值差 <1e-8），
所以差异纯粹来自空间分配：

| 指标 | B1_uniform | B2_uncertain | 谁更好 |
|---|---:|---:|---|
| PSNR | 21.3613 | 21.2923 | B1（+0.069 dB） |
| LPIPS | 0.40622 | 0.40776 | B1（−0.00154） |
| E_warp | 5.0458 | 5.1317 | B1（−0.086） |
| tLP | 0.05823 | 0.05718 | B2（−0.00105） |

三个指标一致偏向 B1，只有 tLP 偏向 B2。**在当前配方下，Direction C 的不确定性加权
没有产生可测收益。**

可能原因（未做隔离验证）：`w_adv(u)` 在纹理区开到 1.0、平坦区压到 0.15，
而 GAN 项本身会把高频抖动带进纹理区（B1/B2 的 tLP 都恶化约 20%），
于是"在纹理区放开感知权重"的收益被 GAN 副作用抵消。

**结论必须限定为"当前配方下无收益"，不能推广为"不确定性加权无效"。**

## 五、8 项自检（全过，1.2 分钟）

| 项 | 实测 |
|---|---|
| 1 Step-0 等价性 | 与原始模块浮点前向 **max\|d\| = 0.0000e+00**；与 M1 的 8 位 PNG 比 99.44% 像素相同、最大差 1 级 |
| 2 冻结审计 | **3.37M** 可训练；cleaning/spynet/参照模型全部无梯度 |
| 3 U₁ 归一化 | 000/002/009 均值 **0.319 / 0.273 / 0.311**，q95 均 1.00 |
| 4 warp 方向 | 不 warp 0.0806 → warp 后 **0.0183（−77%）** |
| 5 均值对齐 | \|均值差\| pix 0.00e+00、adv 2.98e-08 |
| 6 梯度与判别器 | 10 步无 NaN；`adv_d` 0.688–0.695 |
| 7 峰值显存 | **5.76 GB**（micro_batch=2，门槛 <6） |
| 8 断点与过拟合 | ckpt 66.8 MB；参数逐位恢复；单 batch 20 步 loss **−32.7%** |

### 三个"假失败"（判据写错，不是代码错）

1. **Step-0 用 float 比 8 位 PNG**：下限 1/255 = 3.9e-3，于是 3.6e-3 被误判。
   改与浮点前向比后逐位相同。
2. **warp 测试取错帧对**：`ref(t[0:5])[1]` 与 `ref(t[1:6])[0]` 来自两条不同前向，
   不是 flow 描述的那一对，比值虚高到 6.29。改同一序列相邻帧后为 0.227。
3. **`occ` 未上采样**：`flow_and_occ` 返回 64×64（对应 256×256 HR），直接乘 HR 张量报
   `size of tensor a (64) must match b (256)`。**该 bug 同时存在于训练与自检脚本，
   且只在 `λ_t>0` 时触发**——若按手册先跑无时序项的 `B0_ctl` 就会漏掉。

## 九、下一步（均未执行）

三臂已把"感知—保真—时序"的斜率测清，下一步必须换手段：

1. **保持 B2b 的感知配方，把 λ_t 提回 0.40–0.50**（B2b 降到 0.20 是错方向）。
   目标：E_warp 从 6.150 拉回 5.15 附近，同时保住 LPIPS 0.401。这是最有把握的一条。
2. **只训上采样尾部**（`upsample1/2 + conv_hr + conv_last`，0.34M），不动传播分支，
   保真损失应显著更小。
3. **384×384 HR 收尾阶段**：从 B2b 的 `best.pth` 续训 1500 步，
   大尺度补回保真。
4. **放弃 7% 的严格门槛**：若接受 LPIPS 0.401 / PSNR 21.02 / E_warp 6.15，
   则 B2b 已全面优于 OSEDiff（0.4771 / 19.812 / 10.251），只是没打赢
   RealBasicVSR 的 E_warp。这是需要你拍板的口径问题。

任选其一都需要新一轮 1500 步（约 3–4.5 小时/臂）。
